We also apologize for the unclear interface description. The Agent-as-Guide receives the task description, scene schema, grasp-bank summary, preference statistics, and production outcome summaries, including failure stages and check results. It outputs a schema-constrained configuration specifying the phase graph, goal relations, per-phase cuRobo constraints and planning/retry budgets, scene and grasp sampling distributions, and optional grasp-bank expansion requests. Preference statistics serve as context for these decisions. The system validates the configuration, samples scenes and retrieves grasps, and instantiates the phase goals and constraints from the sampled scene and retrieved grasp before calling cuRobo.

The following illustrative example shows the interface for placing an object in a target region. Values are illustrative; the runtime validates the configuration against the task schema and geometry.

4. Runtime consumption — pseudocode

The agent specifies symbolic goals and planning settings. The runtime combines them with the sampled scene and retrieved grasp to instantiate numerical planning targets, as described in the paper’s production algorithm.

context = {
    "task": task,
    "scene_schema": scene_schema,
    "grasp_bank_summary": summarize(bank),
    "preference_statistics": preference_statistics(history, bank),
    "production_outcome_summary": extract_outcome_summary(history),
}
config = agent_guide(context)
validate_configuration(config, task, assets)

if requests_expansion(config):
    candidates = dexonomy_generate(expansion_specification(config))
    additions = object_frame_deduplicate(free_hand_filter(candidates))
    bank = versioned_merge(bank, additions)

scene = sample_task_scene(task, assets, config.scene)
grasp = retrieve_grasp(bank, scene, config.grasp)
phases, goals, constraints, budgets = instantiate_task_plan(
    task, scene, grasp, config
)

trajectory = []
for phase in phases:
    segment = curobo_plan(
        phase, goals[phase], constraints[phase], budgets[phase]
    )
    status = offline_check(segment, goals[phase], constraints[phase])
    if status != "feasible":
        outcome = failure_outcome(phase, status)
        break
    trajectory = concatenate(trajectory, segment)
else:
    outcome = mujoco_replay_and_verify(task, scene, grasp, trajectory)

history.append((scene, grasp, phases, outcome))
if whole_task_accepted(outcome):
    isaac_sim_render_and_export(scene, grasp, trajectory)

We agree that success-oriented sampling can overrepresent easy or repetitive cases. We remove near-duplicate grasp candidates before admitting them to the grasp bank. For candidates associated with the same object and hand, the filter compares their object-frame grasp poses and identifies duplicates using position and orientation thresholds:

# Compare candidates for the same object and hand
# using their object-frame grasp poses.
duplicate = (
    position_distance_m <= 0.002
    and rotation_distance_deg <= 3.0
)

Newly generated candidates also undergo physical checks before admission. For example, in one screwdriver grasp-bank expansion round, 11 candidates were generated, one passed the free-hand checks, and one was added to the bank:

{
  "object_key": "screwdriver_right",
  "round": 0,
  "generated": 11,
  "free_hand_passed": 1,
  "object_frame_added": 1,
  "bank_version": 2
}

To address sampling bias, the agent receives coverage statistics and production feedback as preference context and can adjust scene-sampling weights, grasp selection, and planning settings to allocate attempts to underrepresented cases. These adjustments do not relax physical acceptance criteria. Grasp deduplication reduces local redundancy, while feedback-guided sampling is intended to improve coverage; neither alone guarantees a balanced distribution of accepted trajectories.

Abstract

Learning transferable dexterous manipulation policies is constrained by the scarcity of large-scale robot data. Simulation offers scale, but synthesizing dexterous trajectories is substantially harder than for grippers: the data must cover diverse multi-finger contacts and hand–object configurations while satisfying language-specified grasp and motion semantics. We introduce DexSimWAM, which combines an agent-guided, retrieval-based synthetic-data pipeline with large-scale World Action Model (WAM) pre-training and task-specific post-training. Given a task description and verifier feedback, the agent guides scene sampling, grasp retrieval, optimization-based path planning, and bounded expansion of a physically validated grasp bank. Deterministic filters and fixed whole-task verification yield a 16k-hour corpus spanning diverse objects, scenes, grasp styles, and unilateral and bimanual behaviors. On this corpus, we jointly pre-train DexSimWAM for video prediction and dexterous action generation. We then adapt the pretrained WAM through post-training with simulation trajectories, real-robot trajectories, or both, supporting pick-and-place, 6D object reorientation, functional object use, articulated-object interaction, and long-horizon object sorting and cleanup. We also evaluate direct sim-to-real transfer. Experiments on six dexterous manipulation tasks show that DexSimWAM generally outperforms strong baselines in simulation and on real robots.
